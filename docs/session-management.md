# Session Management

How claudekit helps you manage session length and quality.

## The Problem

Claude Code sessions degrade over time in three ways:

1. **Token cost grows.** Every prior message stays in context. Turn 50 carries all 49 previous turns. You pay for all of it.
2. **Quality drops.** More context means more noise. Claude starts confusing earlier work with the current task. It may hallucinate details from earlier in the conversation.
3. **Focus drifts.** Early instructions get buried under code diffs and tool outputs. Claude "forgets" rules and conventions you established at the start.

The sweet spot is 20-40 tool calls per session. After that, consider compacting or starting fresh.

## Session Guard

### What it does

A lightweight bash script runs after every tool call. It counts how many calls happened in this session and warns at thresholds:

| Threshold | Message | What to do |
|-----------|---------|-----------|
| 30 calls | "Context is growing. Consider /compact." | Run `/compact` to compress prior messages |
| 60 calls | "Large context. Run /claudekit:session-reset." | Save progress and start a new session |
| 90+ calls | "Quality will degrade. Start a new session." | Definitely start fresh |

### How it works

The script (`bin/session-guard.sh`) writes two files to the system temp directory:
- A counter file (incremented on each tool call)
- A timestamp file (set on first tool call)

Warnings go to stderr. Claude Code picks these up and shows them to the user.

The script costs zero tokens. It runs outside Claude's context. It adds less than 10ms per tool call.

### The counter resets automatically

The plugin registers a `SessionStart` hook that clears the counter when you start a new Claude Code session. You do not need to do anything. Each session starts at zero.

### Where counters are stored

```
Linux/Mac: /tmp/claudekit-<hash>.count
           /tmp/claudekit-<hash>.started
Windows:   %TEMP%\claudekit-<hash>.count
           %TEMP%\claudekit-<hash>.started
```

The `<hash>` is derived from the project directory path, so different projects have separate counters.

## /compact

Claude Code has a built-in `/compact` command. It compresses all prior messages into a summary. This frees context space and lets you continue the same session.

Use `/compact` when:
- Session guard warns at 30 calls
- You finished one task and are starting another in the same session
- Claude seems to be losing track of what you asked for

`/compact` is a good middle ground between "keep going" and "start a new session."

## /claudekit:session-reset

When `/compact` is not enough, or you want a clean break:

```
/claudekit:session-reset
```

This skill:

1. **Summarizes** what happened in the session (completed work, in-progress items, decisions made, files changed)
2. **Saves** the summary to `.claude/sessions/<date>-<topic>.md`
3. **Tells you** how to continue in a new session

### Session file format

```markdown
# Session: auth-refactor
Date: 2025-04-19 14:30 UTC

## Completed
- Refactored AuthMiddleware to use JWT validation (src/auth/middleware.ts)
- Added token refresh endpoint (src/auth/routes.ts:45-78)
- Updated auth tests (tests/auth.test.ts)

## In Progress
- Rate limiting on token refresh endpoint (started, not tested)

## Decisions
- Chose RS256 over HS256 for JWT signing (team uses asymmetric keys)
- Rate limit set to 10 refreshes per minute per user

## Next Steps
- Finish rate limiting implementation
- Add integration tests for refresh flow
- Update API docs

## Files Changed
- src/auth/middleware.ts
- src/auth/routes.ts
- tests/auth.test.ts
- src/config/auth.ts
```

### Resuming in a new session

Start Claude Code. Tell it to load the session file:

```
Continue from .claude/sessions/2025-04-19-auth-refactor.md
```

Claude reads the file and picks up where you left off. It has the context it needs without carrying the full conversation history.

### Session files are gitignored

The `.gitignore` generated by init includes `.claude/sessions/`. Session summaries are personal working notes, not project documentation.

## Best Practices

### One task per session

The most token-efficient approach. Start Claude Code, do one thing, finish. If you need to do something unrelated, start a new session.

### Use /compact between tasks

If you want to stay in the same session but switch tasks, run `/compact` first. This clears the context from the previous task.

### Save before starting fresh

Always run `/claudekit:session-reset` before closing a session with unfinished work. The 30 seconds it takes to save a summary will save you 5 minutes of re-explaining in the next session.

### Check the session guard

When you see the 30-call warning, ask yourself: "Am I close to done?" If yes, finish up. If no, save and restart. The quality difference between a 30-call session and a 90-call session is noticeable.
